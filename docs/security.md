# Security

Read `docs/architecture.md` first for the trust-boundary diagram. This
document is the operational security reference: what's hardened, what isn't,
credential handling, and the full threat model.

## Design principle

> The AI model can and will do something unexpected. The sandbox's job is to
> make sure that never turns into something expensive or destructive.

We do **not** rely on the model "behaving." Every control here assumes hostile
or simply buggy model output, hostile repository content (README/issue/PR/
commit messages, build scripts, dependencies), and a possible full compromise
of the OpenClaw Gateway process.

## Host hardening (`scripts/install.sh` + `firewall/nftables.conf`)

* **SSH**: key-only auth. `install.sh` **checks** that at least one
  authorized key exists and that `PasswordAuthentication no` /
  `PermitRootLogin prohibit-password` are set, it will not disable password
  auth if it cannot first confirm a working key-based login path, to avoid
  locking you out. It never touches your existing `authorized_keys`.
* **Firewall**: nftables, default-deny inbound. Allowed: SSH (rate-limited,
  22/tcp by default, change via `.env`), OpenClaw Control UI port
  (18789/tcp by default) restricted to your configured LAN CIDR, and
  established/related. Nothing else inbound. See `docs/networking.md` for the
  full ruleset and the `DOCKER-USER` chain interaction (Docker rewrites
  iptables/nftables in ways that bypass naive `INPUT` rules for published
  container ports, this repo's firewall config accounts for that).
* **Unattended upgrades**: `unattended-upgrades` installed and configured for
  security updates only, with automatic reboot disabled by default (you
  reboot on your own schedule; a silently-rebooted always-on box is its own
  failure mode). Toggle via `.env`.
* **Minimal packages**: install.sh installs only what's required (Docker
  Engine + Compose plugin, nftables, unattended-upgrades, curl, jq,
  age/sops for secret handling, fail2ban optional). No desktop environment,
  no unrelated services.
* **Docker daemon hardening**: `userns-remap` is **not** enabled by default
  because it's incompatible with several bind-mount patterns this repo
  depends on and OpenClaw's own sandbox backend; instead every service sets
  its own `user:`, drops all capabilities, and disables `no-new-privileges`
  escapes. This is documented as an explicit trade-off, not an oversight.
  Docker's default `docker-default` seccomp and AppArmor profiles are left
  enabled (not disabled anywhere in this repo).
* **Log rotation**: Docker's `json-file` log driver configured with
  `max-size`/`max-file` in `compose/compose.yml`; host `logrotate` drop-in
  for `/opt/clawshell/logs/`.
* **Resource limits**: per-container `mem_limit`, `cpus`, `pids_limit` in
  compose. Host-level `nofile`/`nproc` are left at distro defaults unless you
  tune `.env`.
* **Time sync**: `systemd-timesyncd` (default on most systemd distros) verified
  enabled by `install.sh`; not reconfigured if already active.
* **Disk usage monitoring**: `scripts/healthcheck.sh` checks `/opt/clawshell`
  and Docker's data root against a configurable threshold and warns.

## Credentials

All secrets live under `/opt/clawshell/secrets/`, mode `700` directory,
mode `600` files, owned by the dedicated `clawshell` system user created by
`install.sh`. Never committed, never baked into images.

| Secret | Where it's used | How it's provisioned |
| --- | --- | --- |
| `MODEL_PROVIDER_API_KEY` | OpenClaw Gateway container env (from `.env`, not the image) | You paste it during `install.sh`'s interactive prompt, or pre-populate `.env` before running |
| `GITHUB_AGENT_TOKEN` | OpenClaw Gateway (git operations, GitHub API tool calls) | Fine-grained PAT or GitHub App installation token, see `github/PROVISIONING.md` |
| `OPENCLAW_GATEWAY_TOKEN` | Gateway's own auth (Control UI / CLI / API) | Auto-generated by `install.sh` via `openssl rand -hex 32` if not already set |
| `QUOTA_GUARD_CA_*` | mitmproxy CA cert/key used to terminate TLS for allowlisted egress | Generated locally on first run by mitmproxy itself; never leaves the box |

`install.sh` refuses to proceed if `.env` still contains the literal
placeholder strings from `.env.example` (checked by string match) for any
required secret. Secrets are never printed to stdout/logs; `healthcheck.sh`
and `backup.sh` only ever report *presence*, not values.

## Threat model

| Threat | Mitigation |
| --- | --- |
| Prompt injection via README/issue/PR/commit content | OpenClaw's own docs treat all inbound content as untrusted by default; we add: the target is mounted **read-only** (`:ro`) so the agent *cannot* write to it even if tricked, the only writable output is the markdown report under `reports/`, and the egress allowlist prevents exfiltration to arbitrary hosts |
| Malicious repository / malicious dependency (supply-chain) | Test/build execution happens inside the nested rootless-DinD sandbox on the internet-less `clawshell-sandbox` network, a malicious `npm install` cannot reach the internet to exfiltrate or pull a second-stage payload beyond what quota-guard's allowlist permits (and the sandbox network has no route to quota-guard's allowlisted hosts at all, by design, build sandboxes get **no egress**, full stop; see `docs/networking.md`) |
| Arbitrary shell commands | Confined to the OpenClaw sandbox container (non-root, dropped caps, read-only rootfs except workspace, resource limits) |
| Credential theft / secret exfiltration | Secrets are bind-mounted only into the Gateway container, never into the sandbox execution containers where model-controlled code actually runs (see compose file, `sandbox-dind`/sandbox containers get zero secret mounts); egress allowlist blocks exfiltration to non-allowlisted hosts even from the Gateway |
| Lateral movement to other LAN hosts | nftables default-deny + isolated Docker networks with no route to your LAN except any single internal host you explicitly allowlist |
| Docker privilege escalation | No `docker.sock` mount anywhere; sandbox gets a rootless nested Docker daemon instead of the host's |
| SSRF (model tricks a tool into calling an internal LAN service) | Deny-by-default egress allowlist at quota-guard is host/IP based, not just DNS-name based, it resolves and pins destination IPs so DNS rebinding can't bypass it (see `docs/networking.md`) |
| Destructive commands (`rm -rf`, force-push, etc.) | The target is mounted **read-only** (`:ro`), the filesystem rejects any write/delete to the analysis target; the only writable area is the `reports/` output; backups run independently of agent activity. ClawShell never pushes, branches, or commits |
| Runaway agent loops / quota exhaustion / excessive API usage | quota-guard circuit breaker + `scripts/pentest-task.sh` per-task hard limits, see `docs/quota-protection.md` |
| Attacker-controlled repository added to the allowlist by mistake | Documented operational practice: only add repos you trust; the target is cloned read-only and never written back, so a malicious target cannot be modified or used as a push vector |

### What we explicitly do **not** claim to solve

* OpenClaw's sandbox is documented upstream as "not a perfect security
  boundary", we do not claim our additional layers make it one. They reduce
  blast radius; they do not guarantee containment against a sufficiently novel
  container escape.
* We cannot fully prevent a sufficiently motivated model from *trying*
  something destructive within its own workspace/branch, we prevent it from
  reaching `main`, other repos, other hosts, or unlimited spend.
* mitmproxy TLS interception requires trusting a locally-generated CA inside
  the OpenClaw container only. If a provider pins certificates (most don't
  for standard REST APIs) that call will simply fail closed rather than
  bypass the proxy, treated as a normal blocked-egress event, logged.

## Reporting / operating

Run `./scripts/healthcheck.sh` regularly (or via the provided systemd timer)
to see agent state, quota state, network health, and blocked-connection
counts in one place.
